# 质量门禁（quality-policies）

本目录包含两部分：**门禁定义**（`rep-valuation-quality.json`）与**门禁执行器**（`gate_runner.py`）。

> 评审 P2-3 指出：门禁 JSON 写得完整，但仓库里**没有跑门禁的代码**，"对比度 AA""排版审计"这类人工检查被列为 hard gate，可执行性存疑，"数字与底座逐 token 一致"对格式化/舍入很脆弱——**门禁只是政策声明，不是可执行的验收程序**。

---

## 一、用法

```bash
# 用仓库内试运行产物自检（默认）
python3 quality-policies/gate_runner.py

# 指定报告与数据底座
python3 quality-policies/gate_runner.py --report <报告.md> --baseline <数据底座.csv>

# 机读输出（CI 用）
python3 quality-policies/gate_runner.py --json

# 调整数字比对容差
python3 quality-policies/gate_runner.py --tolerance-pct 1.0
```

退出码：`0` 可交付（无硬门失败）；`1` 存在硬门失败。

---

## 二、门禁清单与执行方式

| 门禁 | 级别 | 执行方式 | 检查内容 |
|---|---|---|---|
| `placeholder-clean` | hard | **automated** | 未填占位符残留（方括号占位、`TO`+`DO`、`XX`+`X`、待填写 等，模式字面量在代码中拆开构造以免自触发） |
| `no-banned-tokens` | hard | **automated** | 禁例 token 扫描（从门禁 JSON 读取），命中给行号与上下文 |
| `numbers-match-dataset` | hard | **automated** | 报告数字与数据底座一致性（见第三节） |
| `caliber-declared` | hard | **automated** | 含量值的行能否归属标注级（引用/测算/估算/研判推断/待补） |
| `interval-required` | hard | **automated** | 估值结论是否给出区间；检出疑似单点断言 |
| `outline-match` | soft | **automated** | 章节与 `output-templates/rep-valuation.json` 逐项对照 |
| `render-no-overflow` | hard | **declarative** | 渲染 0 溢出 + 对比度 AA（双视口）——**不可自动执行** |
| `layout-audit` | soft | **declarative** | 排版审计——**不可自动执行** |

### 关于声明性（declarative）门禁

`render-no-overflow` 与 `layout-audit` 需要真实渲染环境与视觉判断，本执行器**不为其判定通过**，而是标记为 `declarative` 并输出人工检查项。

> **为什么不做成"永远 pass"的假检查**：伪造通过比不检查更危险——它会让人以为门禁已覆盖，从而放松人工把关。声明性项在输出中显示为 `◇`，并计入"以下 N 项不可自动执行"，不计入质量分（既不奖励也不惩罚）。

## 三、数字比对的归一化与容差（关键设计）

评审指出 token 级匹配"对格式化 / 舍入很脆弱"。脆弱性有两个来源，本执行器**分别处理**：

### 3.1 格式差异 → 归一化

| 形式 | 归一化 |
|---|---|
| 千分位逗号 | `47,700` → `47700` |
| 全角数字 | `４７７００` → `47700` |
| 百分数与小数 | `2.24%` → `0.0224`（比对时双向尝试） |
| 单位 | `万元` → ×10⁴；`亿元` → ×10⁸ |
| 区间写法 | `48,500–51,700` / `1.50-1.58` → 拆为两个数 |

> ⚠️ **区间连字符的坑（真实踩过）**：底座里的 `1.50-1.58` 若不先消解连字符，会被解析成 `1.50` 与 **`−1.58`**，于是正文的 `1.58%` 被判为冲突。这正是评审说的脆弱性。执行器在抽数前统一把"数字-数字"之间的 `- – — ~ ～ 至` 视为区间分隔符。

### 3.2 四舍五入 → 按书写精度放宽

```
允许误差 = max(相对容差 × 量级,  0.5 × 10^(−书写小数位数))
```

例：底座 `1.68`，报告写「约 **1.7%**」。只按 0.5% 相对容差算，`|1.7−1.68|/1.7 = 1.18%` 会被误判为冲突；按书写精度（1 位小数 → 允许 0.05）则正确判为一致。

**实际使用的容差会显示在输出里**（`相对容差 0.50% + 按书写精度放宽`），不悄悄放宽。

### 3.3 冲突 vs 待核（避免误报淹没真问题）

报告里的数字有三类来源：底座量值、外部引用、非量值（年份/序号）。若把"底座里找不到"一律判失败，会产生大量伪报，**门禁就会被人为绕开**。因此本执行器区分：

| 判定 | 条件 | 是否阻断 |
|---|---|---|
| **一致** | 命中底座（归一化+容差后） | 否 |
| **冲突** | **指标名紧邻窗口**内的数字与底座同指标值不符 | **是** |
| **待核** | 像量值但底座中找不到（外部引用） | 否（仅提示） |

**"紧邻窗口"是核心**：只在指标名之后、到下一个 `|` / `。` / `；` 或 40 字符为止的窗口内比对。若把"整行出现的指标名"与"整行所有数字"配对，一行里的序号、年份、其他指标值都会被判冲突——这正是最初的实现犯过的错（首次运行 18 处"冲突"全是误报）。修正后为 **0 冲突**。

## 四、实测结果（对本包试运行产物）

以 `_pack_build/trial_run/北京远洋山水南区-定价报告-v2含方法论.md` + `数据底座表.csv` 自检：

| 门禁 | 结果 | 说明 |
|---|---|---|
| placeholder-clean | ✓ | 0 处 |
| no-banned-tokens | ✓ | 扫描 4 个禁例 token，0 命中 |
| numbers-match-dataset | ✓ | 命中底座 **184 处，冲突 0 处**，待核 78 处 |
| caliber-declared | ✗ | 含量值 81 行中仅 13 行可归属标注级（16%），低于底线 60% |
| interval-required | ✓ | 检测到区间表述，0 处疑似单点断言 |
| outline-match | ! | 模板 10 节，缺 5 节（该报告早于 v0.3.0 模板） |
| render-no-overflow | ◇ | 声明性 |
| layout-audit | ◇ | 声明性 |

**质量分 78 / 100**，结论：不可交付（`caliber-declared` 硬门失败）。

### 这次自检发现的两类真实问题

1. **单位不一致（已在底座侧修复）**：报告写「价格租金比约 **56.5–59.4 年**」，而底座记为 `678 月`——同一指标两个单位口径，底座未登记"年"口径。已在底座补登 `价格租金比(年) 56.5-59.4 年`。
2. **标注密度不足（未修复，属真实缺陷）**：该报告是 v0.1.1 期产物，只在正文一处集中声明四级标注，**没有把每个数字锚到标注级**。v0.3.0 的输出模板已把「每个量值须带标注级」写成硬要求，后续报告应按新模板产出。

> 这正是"门禁可执行"的价值：以上两条都不是靠人读报告能发现的，而门禁一跑就出来了。

## 五、接入 CI

```bash
python3 quality-policies/gate_runner.py --report "$REPORT" --baseline "$BASELINE" --json || exit 1
python3 source/check_manifest.py || exit 1
python3 adapters/registry.py --selftest || exit 1
python3 -m unittest discover -s tests -v || exit 1
```

四项分别覆盖：**报告质量门禁 / 溯源一致性 / 数据契约实现 / 数值回归**。任一失败即阻断交付。
