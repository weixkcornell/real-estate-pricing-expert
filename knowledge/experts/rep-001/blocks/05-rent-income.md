## 为什么收益法是交易法之外的"独立证据"

交易定价回答"市场现在愿意出多少"，收益法回答"这处物业的现金流本身值多少"。两者的差额就是**市场对资本增值的隐含预期**——这是本包场景 DAG 强制双视角交叉验证的原因（评审 2.4 认可该设计）。

```
资产价值 = 未来净现金流的现值
         = NOI / Cap Rate           （永续年金近似）
         = Σ_t  NOI_t / (1+r)ᵗ + 期末价值/(1+r)ⁿ   （DCF 完整式）
```

## mat-017　Ghysels, E., Plazzi, A. & Valkanov, R. (2007). *Valuation in US Commercial Real Estate*. European Financial Management, 13(3), 472-497. DOI 10.1111/j.1468-036X.2007.00369.x

### 模型设定
商业地产估值的**收益—资本化框架**与预测回归。核心关系：

```
V_t = NOI_{t+1} / CapRate_t
```

同时系统检验 **cap rate 与租金增长、折现率、风险溢价**的关系，并做收益预测回归：

```
R_{t+1} = α + β·CapRate_t + γ·X_t + ε_{t+1}
```

### 关键结论
- Cap Rate **不是常数**，随周期系统性变化；用它做估值必须说明是当期 cap rate 还是长期均值；
- Cap Rate 对后续收益具有**预测力**（类似股息收益率对股票收益的预测）——说明 cap rate 内含时变风险溢价；
- 因此"用当前 cap rate 直接外推长期价值"会产生系统性偏误，**须做敏感性分析**。

### 数据要求
需要**租金（NOI）与交易价格配对**形成 cap rate 序列，且分物业类型。美国有 NCREIF / 公开 REITs 数据支撑。

### 中国适配注意点（**本族最大的数据缺口**）
中国**没有公开、连续、分城市分类型的 cap rate 序列**。因此：
- 不能引用"某城市写字楼 cap rate 为 X%"这类无来源数字（违反本包禁例）；
- 替代方案有两条，且**必须显式标注为推导而非引用**：
  1. **匹配价格租金比的倒数**：`CapRate ≈ 年租金 / 价格`；但该比值是**毛资本化率**，未扣运营成本，须先估算 NOI 率（通常毛租金扣 20–35%）；
  2. **交易反推**：有大宗交易时用 `NOI / 成交价` 逐笔反推，形成点估计序列。
- 本包 P2 修订新增 **cap rate 标定器**（`rent_model.py --method caprate-calib`）实现第 1 条路径。

## mat-018　Fisher, J.D., Miles, M.E. & Webb, R.B. (1994). *An Integrated Approach to the Evaluation of Commercial Real Estate*. Journal of Real Estate Research. DOI 10.1080/10835547.1994.12090743

### 模型设定（**DCF / 收益法工程化**）
把"投资评价"与"资产估值"整合为统一的现金流折现框架：

```
V₀ = Σ_{t=1}^{n}  NOI_t / (1+r)ᵗ  +  V_n / (1+r)ⁿ
```

关键结构要素：
- **NOI（净营运收入）**＝ 有效毛租金收入 − 运营费用（不含折旧、利息、所得税）；
- **有效毛收入**＝ 潜在毛租金 ×（1 − 空置与收租损失率）＋ 其他收入；
- **再售价值 `V_n`**：通常用退出时的 cap rate 反推 `V_n = NOI_{n+1} / CapRate_exit`；
- **折现率 `r`**：由资本资产定价思路确定（无风险利率 + 房地产风险溢价），或由市场参与者的目标收益率反推。

### 方法纪律（**避免循环论证**）
DCF 的常见致命错误：**用 `V₀` 反推的 cap rate 再去算 `V_n`**，等于假设"我的估值是对的"。规范要求：
- 退出 cap rate 应来自**独立的市场观察**（同期可比交易的 cap rate），并做敏感性分析；
- **必须报告折现率与退出 cap rate 的二维敏感性表**（本包 `rent_model.py --method dcf` 输出该表）。

### 数据要求
逐期 NOI 预测（租金增长率、空置率、费用率假设）+ 折现率 + 退出 cap rate。**假设必须逐项列示来源**，不可只给终值。

### 中国适配注意点
- 中国商业物业（写字楼、商铺）**空置率与租金指数缺乏权威公开序列**，NOI 预测的输入不确定性极高 → 应以**区间形式**输出估值，且区间来源须分解为"租金假设区间"与"cap rate 假设区间"两部分。
- 住宅出租的**税费与持有成本结构**与商业不同（个人出租住宅的综合征收率、增值税起征点等），必须按物业类型分别建税费模板。

## mat-019　（2021）*The user cost of housing and the price-rent ratio in Shanghai*. Regional Science and Urban Economics, 89, 103676.

### 模型设定（**用户成本法**——解释"为什么中国房价房租比这么高"）
**用户成本（user cost）**是持有房产一年的隐含成本：

```
UC = P · [ i·(1−τ) + δ + m − π_e ]        （简化式，各项含义见下）
```

| 符号 | 含义 |
|---|---|
| `i` | 资金成本（房贷利率或机会成本利率） |
| `τ` | 利息抵扣税率（若有） |
| `δ` | 折旧与维护率（住宅经验区间约 1–3%/年，按房龄调整） |
| `m` | 房产税等持有税费率（中国住宅目前试点城市外基本为 0） |
| `π_e` | **预期资本增值率** |

**均衡条件**：无套利时，年租金应等于用户成本：
```
R = UC  ⇒  P/R = 1 / [ i(1−τ) + δ + m − π_e ]
```

即**价格租金比是用户成本的倒数**。该文以上海数据检验此关系的解释力。

### 关键结论（**中国估值的核心逻辑**）
- 中国城市 `P/R` 远高于国际水平，**不能简单判为泡沫**：在 `m ≈ 0`（无持有税）、`i` 较低、且 `π_e`（预期增值）为正且不低时，**高 `P/R` 可以是理性的均衡结果**；
- 反之，一旦预期增值 `π_e` 转负（或持有税落地），`P/R` 的均衡值会显著下移 → **价格对预期极度敏感**；
- 因此估值报告必须把 `π_e` 作为**显式假设**列出，并做敏感性分析，而不能隐含假设。

### 数据要求
利率（公积金 / 商贷）、折旧维护率、持有税政策、租金水平、价格水平。中国参数多数可得，但 `π_e` **不可观测**——只能作为情景假设（本包纪律：标为「研判推断」而非「测算」）。

### 中国适配注意点（**本族最有价值的一条**）
用该方法解读中国住宅估值的标准表述应为：

> 以用户成本法校准：在资金成本 i、折旧维护率 δ、持有税费率 m、预期增值率 π_e 的给定假设下，均衡价格租金比为 `1/[i(1−τ)+δ+m−π_e]`。当前观测价格租金比高于该均衡值 → 隐含的 `π_e` 需达到 X% 才能成立（反推）。该 `π_e` 是否可信，即为本报告的核心判断。

**这个"反推隐含预期"的写法，比直接说"收益率低所以投资价值弱"严谨得多**，因为它把结论落到可检验的假设上。本包 `rent_model.py --method user-cost` 已实现反推逻辑。

## mat-020　Song, Z., Wilhelmsson, M. & Yang, Z. (2020). *Constructing a rental housing index and identifying market segmentation: Beijing, China*. KTH Working Paper 20/10.

### 模型设定（**分层时间虚拟租金指数**）
把特征价格与时间虚拟结合，用于**租金**指数构建：

```
R^(λ) = Xβ + Σ_t δ_t·D_t + ε        （λ 为 Box-Cox 参数，λ=0 即半对数 ln R）
```

- `X`：租赁属性（面积、户型、楼层、装修等）；
- `Σ_t δ_t·D_t`：各期虚拟变量，`δ_t` 即质量调整后的租金变化；
- `λ` 由极大似然确定，**仅用于检验函数形式**；指数构造以半对数（λ=0）为主口径
  （理由见下节"租金指数的一个方法论陷阱"）。

### 关键结论
- **市场分割显著**：北京不同区域的租金走势不一致，单一全市租金指数会掩盖结构差异；
- 因此租金指数必须**分层输出**（按行政区 / 户型 / 楼龄分层），并在报告中标明分层依据。

### 数据要求
租赁样本（含面积、房型、区位）+ 期次。租赁数据的属性披露质量低于买卖（装修、朝向常缺失），
须先做缺失处理并显式声明。

### 中国适配注意点
- 中国租赁市场**机构化程度低**（个人房东占多数），报价与成交差异大 → 须统一为**等效月租**
  （"押一付三""年付折扣"等支付条款会扭曲名义租金）；
- **合租/分租普遍**：样本中须剔除或单独分层"单间出租"，否则会把房间数当整租属性
  （本包 `RentAdapter` 已内置面积 <20㎡ 的合租检出）；
- 租赁数据多来自挂牌披露，口径为**挂牌租金**，与成交租金存在差异，须标注。

## 租金侧的独立方法（与 mat-017/018/019 互补）

| 方法 | 要点 | 代码入口 |
|---|---|---|
| Hedonic 租金 | 用属性解释单位租金（元/㎡/月），识别面积效应、装修溢价 | `rent_model.py --method hedonic-rent` |
| 分层时间虚拟租金指数 | `R^(λ) = Xβ + Σδ_t D_t`，`λ` 由 Box-Cox 似然定；**指数用半对数口径** | `rent_model.py --method rent-index` |
| 匹配价格租金比 | 同小区/同户型配对租金与价格 → 消除结构差异的租价比 | `rent_model.py --method matched-pr` |
| Cap Rate 标定 | 毛租价比倒数 × NOI 率 → cap rate 点估计区间 | `rent_model.py --method caprate-calib` |
| DCF | 完整现金流折现 + 二维敏感性 | `rent_model.py --method dcf` |

### 租金指数的一个方法论陷阱（来自本包 R4 迭代，**已修复**）
Box-Cox 与半对数形式的**似然归一化项不一致**（相差 `Σ ln R`，量级数百）→ 若两者走不同分支，模型选择必然偏向半对数。且 `λ ≠ 0` 时 `exp(δ_t)` 不再是租金比。

→ 修复：统一参数化；指数改在**平均属性上比较各期拟合租金**，对任意 `λ` 都成立；并以**半对数为主口径、选中 `λ` 为诊断口径并列报告**。

**这对应一条更普适的纪律**：任何"模型选择"比较，必须先确认各候选的似然/损失函数**归一化项一致**，否则比较结果无意义。
